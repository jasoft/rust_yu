# 软件工具信息架构

## 目的

旧版“证据与策略”把软件记录检查、后台暂停、软件清单对比和清理安全规则放在一个入口中。它们面向不同任务，用户无法从名称判断应该何时进入、操作是否会修改电脑。

新版按用户要完成的事情安排入口，不再暴露内部的 F-14～F-20 路线编号、Evidence、Audit、Safe、Recovery 等实现术语。

## 功能归属

| 用户要完成的事情 | 新入口 | 系统影响 |
|---|---|---|
| 查看软件当前的安装来源、卸载清单和签名 | 应用管理 → 选中软件 → 安装记录 | 只读检查；不会扫描或删除残留 |
| 查找软件可能留下的文件、用户数据和系统记录 | 应用管理 → 选中软件 → 深度分析 | 只读扫描；完成后先停留在扫描页，用户确认后再查看和处置结果 |
| 暂停某个软件的自启动项或后台服务 | 启动项管理 → 按软件暂停 | 先生成只读计划；确认后只禁用可证明归属且可恢复的项目 |
| 比较两台电脑或两个时间点的软件差异 | 软件清单对比 | 只读比较；不下载、不安装、不卸载 |
| 了解 Rust Yu 如何保护清理操作 | 设置 → 清理安全规则 | 说明强制执行的规则，不提供绕过保护的模式开关 |

## 安全边界

- 安装记录只展示当前清单、安装目录和签名等来源，不伪装成安装历史；深度分析才负责查找残留。
- 低置信度、未知归属、共享组件和系统关键项目默认保留。
- 普通清理必须经过预览、备份和确认；目标发生变化时停止执行。
- 恢复不会覆盖后来重新出现或已经改变的内容。
- 文件粉碎等不可恢复操作保持独立入口、独立警告和独立确认。

## 保留的后端能力

本次只重构产品信息架构和交互文案，不降低原有安全门禁。安装记录重建、休眠计划与回滚、带 SHA-256 的软件清单、基线只读比较和 Safe 清理校验继续由原 Tauri/Rust 命令执行。
